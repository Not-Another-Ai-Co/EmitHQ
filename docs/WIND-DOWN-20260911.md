# EmitHQ — wind-down record (2026-09-11)

**Status: INACTIVE, not deleted.** EmitHQ was an exploratory product. On 2026-09-11 it was wound down to a state that stops ongoing spend and can be revived. The domain is kept.

This repository is public, so this record carries no vendor account or resource IDs. The full operational record lives outside the repo, in the maintainer's private artifacts: resource IDs, measurement commands, and the exact API calls to reverse each step.

## What was stopped

| surface                                      | action (2026-09-11)                                                                                                                                                                                                                  | reversible |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- |
| Railway: API + delivery worker               | GitHub auto-deploy from `master` disabled on both services; active deployments stopped and removed. `https://api.emithq.com/health` went 200 → 404. Services, variables and the `api.emithq.com` custom domain are still configured. | yes        |
| Local Umami analytics (`docker-compose.yml`) | `docker compose down` without `-v`: containers removed, data volume kept                                                                                                                                                             | yes        |

Spend before: about $12/month (Railway usage ≈ $2, Neon ≈ $0.04, Upstash $10). After this wind-down: about $10/month, falling to about 1¢ once the Upstash database is deleted.

## Data

Both databases were dumped on 2026-09-11 (`pg_dump -Fc`) and **restore-tested row for row** in throwaway containers.

- Neon Postgres 17: 10 tables, 2,186 rows, RLS policies intact.
- Umami: 14 tables, 287 rows.

The dumps sit under `backups/2026-09-11/`, which is gitignored. An offsite copy is pending.

## To bring EmitHQ back

Order matters: `/health` probes Postgres and Redis (see `ARCHITECTURE.md` → Monitoring & SLOs), so the data and queue come before compute.

1. **Postgres.** If the Neon project still exists, nothing to do. Otherwise:
   1. Create a Postgres 17 project in `aws-us-east-1`.
   2. Create roles `app_admin` (LOGIN, BYPASSRLS) and `app_user` (LOGIN).
   3. `pg_restore -v -d "<unpooled owner connection string>" backups/2026-09-11/neon-emithq.dump`. Two errors about the Neon-internal `cloud_admin` role are expected and harmless.
   4. Check row counts against `backups/2026-09-11/neon-source-counts.txt`.
   5. Update the `database` item in the `EmitHQ` 1Password vault.
2. **Redis.** Create an Upstash Redis database (Fixed 250MB) and update the vault `redis` item (`host`, `password`). The queue starts empty by design: messages are persisted to Postgres before enqueue (DEC-023).
3. **Secrets.** Refresh the Railway service variables that changed. `.env.tpl` lists every variable. The `api` service also carries `QSTASH_*` and `REDIS_URL`/`REDIS_TOKEN`; the `worker` needs only the database, Redis, Clerk publishable key and `NODE_ENV`.
4. **Compute.** Re-enable GitHub auto-deploy (`master`) on both Railway services and deploy the current `master`. Verify `https://api.emithq.com/health` returns 200.
5. **Monitoring.** Unpause the Better Stack monitor for `api.emithq.com/health`.
6. **Analytics (optional).** `op run --env-file=.env.tpl -- docker compose up -d umami umami-db` (the volume was kept).
7. Clerk, Stripe, Vercel, Sentry, Resend, Cloudflare: untouched, nothing to do.
